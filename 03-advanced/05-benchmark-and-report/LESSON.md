# 05 · 독립 벤치마크와 보안 모델 리포트

좋은 보고서는 최고 숫자만 보여주지 않는다. 데이터 출처와 기간, 중복 제거, group split, 라벨 가이드, seed,
threshold, 모델 버전, 하드웨어, slice, 실패 사례, 알려진 한계를 함께 적는다.

공개 벤치마크는 비교 가능성이 장점이지만 학습 데이터와 겹치거나 반복 튜닝으로 오염될 수 있다. 공개 데이터,
자체 검수 holdout, 정상 운영 분포의 세 축을 분리해 보고한다. 가능한 경우 표본 수와 bootstrap 신뢰구간도 낸다.

고객·이해관계자에게 “탐지율 99%”만 제시하지 않는다. 어떤 분포에서 어떤 threshold로 얻었는지, 정상 차단률과
간접 입력 성능, 어떤 공격을 아직 놓치는지 함께 설명한다.
